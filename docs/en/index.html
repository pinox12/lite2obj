What it does

Faithful to Minecraft, comfortable in Blender.

It is not a box converter: it respects blockstates, variants, rotations, UVs, transparency, biome tints and the game's culling rules.

Game-accurate mesh

Blockstates, multipart, model inheritance, variant and element rotations, explicit UVs and uvlock like vanilla.

Atlas and tints

Packs every texture into an atlas with padding and transparency modes. Grass, leaves and water get their biome colour.

Real culling

Drops faces against opaque cubes, matching glass, panes and fences. Fluids share corner heights and form continuous slopes.

Entities and block entities

Chests, banners, skulls, frames, boats, minecarts and optional mobs, with vanilla matrices and poses.

Ready for Blender

OBJ with quad faces, an MTL with a single atlas material and the atlas PNG. No intermediate steps or plugins.

App and CLI

3D viewer with orbit, grid, wireframe and layer slicing, or info, list and export commands for automation.

How it works

Three steps and you're in Blender.

The app does not scan your disk for Minecraft installs or schematics. You pick the files; it does the rest.

Open your .litematic

Drag it onto the window or use Open schematic…. You'll see the mesh in the 3D viewer before exporting.

Generate the asset pack

Pick your client.jar once. lite2obj extracts blockstates, models and textures into a local .l2oassets.

Export to OBJ

Choose a folder and a name. Import the .obj into Blender with the .mtl and atlas.png next to it.

Assets made simple

Textures do not ship with the build.

GitHub Releases builds are published without lite2obj-assets.l2oassets or Minecraft textures: the content is copyrighted and each user generates their own file from the jar of their version.

It's a one-time step. After that, lite2obj uses that pack for every render, without asking for the jar again or scanning the disk.

  • No auto-detection of Minecraft, versions or resource packs.
  • Optional resource packs, added manually as .zip files or folders.
  • ⚠ warning when the schematic uses blocks that are not in the pack.
⚠
Missing blocks? The pack is older than your schematic. Regenerate the assets with a newer client.jar from File → Generate asset pack….
terminal 
# From the app
File → Generate asset pack…

# Or from the CLI
$ uv run lite2obj assets build --jar client.jar
$ uv run lite2obj assets info

# Export the schematic
$ uv run lite2obj export house.litematic output/ --name house

Frequently asked questions

What you usually need to know.

Do I need Minecraft installed?

No. You only need the client.jar of the version you use to generate the asset file once. lite2obj does not look for Minecraft installs, launchers or folders on your disk.

Where is the .l2oassets file stored?

On Linux, in ~/.local/share/lite2obj/. On Windows, in %LOCALAPPDATA%\lite2obj\. You can also set a specific path with the LITE2OBJ_ASSET_PACK environment variable.

The panel shows ⚠ and some blocks are missing. What should I do?

It means the schematic uses blocks that are not in your pack (usually from a newer version). Regenerate the assets with a recent client.jar from File → Generate asset pack…. Blocks that cannot be resolved are skipped; the rest of the schematic still renders.

Can I use resource packs?

Yes. Add them manually with Add .zip… (you can select several) or Add folder…. Enable them with checkboxes and sort them by priority. Packs are never scanned from disk.

How do I open a .litematic with a double click?

From the app: File → Associate .litematic files…. On Linux it creates a .desktop entry and the MIME type in your profile; on Windows it writes the HKCU\Software\Classes keys. No admin rights needed, and you can undo it from the same menu.

Why doesn't the GitHub build include textures?

Because Minecraft assets are copyrighted. The repository and releases only publish the code and executables; the asset file is generated on your machine from your own jar.

How do I build the app from source?

Install uv, run uv sync and then uv run lite2obj gui. To build the AppImage or the .exe, use the scripts in packaging/. Full instructions are in the repository README.
